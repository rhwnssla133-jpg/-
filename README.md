# OK익스프레스 홈페이지

광주광역시 OK익스프레스의 정적 홈페이지입니다. 제작 기준일은 **2026년 10월 19일**입니다.
빌드된 사이트와 업로드 ZIP을 포함하며, 온라인 계약·결제·광고 추적은 없습니다.

**Google 스프레드시트 + 내 Google 이메일 알림 추가 코드:** [계정 설정 순서와 코드 안내](docs/GOOGLE-SHEETS.md). 이 방식은 GitHub 연동으로 Netlify Functions까지 배포해야 하며, 정적 ZIP만 올려서는 서버 연동 코드가 배포되지 않습니다. 아직 실제 Google 계정 연결은 하지 않았습니다.

**현재 배포본은 전화 문의 모드입니다.** 사업자 상세정보, 개인정보 담당자, 국외이전 조건이 제공되지 않아 온라인 문의를 잠갔습니다. 계정과 메일함 접근 권한이 없어 실제 Netlify Forms 기록 생성과 네이버메일 수신은 검증하지 않았습니다. 수신 주소를 설정 파일에 적은 것은 메일 연결 완료를 뜻하지 않습니다.

공식 문서 URL을 조회했지만 이 환경의 네트워크 프록시가 `403 Forbidden`으로 차단했습니다. 아래 배포 절차는 구현에 맞춘 실행 안내이며, 현재 서비스 화면·DPA·법령을 확인 완료했다는 의미가 아닙니다. [자료 확인 현황](docs/SOURCES.md)을 읽고 실제 배포 시 공식 문서와 계정 설정을 다시 확인하세요.

## 1. 파일과 미리보기

**설치 없이 화면을 확인하려면** `artifacts/ok-express-preview.html`을 내려받아 브라우저에서 여세요. 스타일·그림·홈·개인정보·보상 안내를 한 파일에 담은 미리보기이며 온라인 접수는 잠겨 있습니다. 보안 관리 정책으로 로컬 HTML 열기가 차단된 컴퓨터에서는 아래 HTTP 서버 방식으로 확인하세요. 새로 생성하려면 빌드 후 `python3 scripts/preview.py`를 실행합니다.

| 파일 | 용도 |
| --- | --- |
| `dist/` | 빌드 완료된 정적 배포 폴더. `index.html`이 최상단 |
| `artifacts/ok-express-netlify.zip` | `dist/`의 실제 HTML·CSS·JS·SVG를 포함한 업로드용 ZIP |
| `ok-express-netlify.zip` | GitHub에서 내려받을 수 있도록 저장소 루트에도 제공하는 같은 배포 ZIP |
| `artifacts/ok-express-source.zip` | 편집 가능한 원본·설정·문서·테스트 |
| `config.json` | 상호·연락처·사업정보·개인정보·접수 활성화 설정 |

Python 3.12 이상에서 프로젝트 폴더로 이동한 후 실행합니다.

```sh
python3 scripts/build.py
python3 -m http.server 8000 --bind 127.0.0.1 --directory dist
```

자신의 컴퓨터에서 브라우저로 `http://127.0.0.1:8000`을 엽니다. 이 주소는 로컬 미리보기용이며 공유·배포 주소가 아닙니다. 실행을 끝내려면 터미널에서 Ctrl+C를 누릅니다. 클라우드 온보딩 화면은 localhost 미리보기 링크를 지원하지 않으므로 ZIP을 내려받아 로컬에서 확인하거나 Netlify 배포를 이용하세요. 로컬 미리보기에서는 폼 설정을 모두 채워도 접수를 허용하지 않습니다. 서버가 돌고 있다는 사실만으로 Netlify 접수나 알림이 연결되지는 않습니다.

빌드에는 npm 설치나 외부 라이브러리가 필요 없습니다. 새 작업에서도 기존 체크아웃을 사용하며 별도 Git worktree를 만들 필요가 없습니다.

## 3. 미확정 항목 채우기

`config.json`의 `null`과 `false`는 누락을 숨기지 않기 위한 기본값입니다. **가짜 값이나 임시 국가를 넣어 활성화하지 마세요.** 확인되지 않은 항목은 ‘확인 필요’ 상태로 남깁니다. 빌드하면 미확정 키가 출력됩니다. 이 로그에는 고객 문의 내용이 포함되지 않습니다.

| 설정 | 확인할 내용 |
| --- | --- |
| `business.representative` | 실제 대표자명 |
| `business.registrationNumber` | 실제 사업자등록번호 |
| `business.address` | 실제 사업장 상세주소 |
| `business.transportPermit` | 실제 운송·주선 관련 허가정보 또는 적용 여부와 근거 |
| `business.openingHours` | 실제 운영시간. 24시간이라고 추정하지 않기 |
| `business.insuranceDetails` | 실제 가입 여부와 내용. 미가입이라면 확인한 사실로 기록; 가입 홍보로 전환하지 않음 |
| `privacy.responsiblePerson`, `department` | 실제 담당자·부서 |

| `privacy.manualDeletionProcedureConfirmed` | 원본·메일·휴지통 삭제 담당자와 일정 확인 후에만 `true` |

상호·연락처·알림 수신 주소의 기준은 이 파일입니다. `scripts/build.py`가 각 화면의 반복 정보를 채웁니다. `dist/`를 직접 수정하면 다음 빌드 때 사라집니다. 안내문 본문은 `scripts/build.py`, 화면 구조는 템플릿, 스타일은 CSS, 검증·제출 처리는 JS에서 수정합니다. 설정 파일에는 비밀번호나 API 키를 넣지 않습니다.

운영시간·보험정보는 현재 관리 설정에만 남겨 두며, 공개 홍보 문구로 자동 출력하지 않습니다. 사업자명·등록번호·주소·허가정보는 확인된 값을 빌드하면 푸터와 방침에 반영됩니다. 구성값이 들어갔다는 사실이 법적 적합성 검증을 의미하지는 않습니다.

## 4. 국외이전·위탁 확인 후 접수 활성화

Netlify의 **현재 계정에 적용되는 DPA, Forms 처리 위치, 알림 전송 경로, 재위탁 현황**을 확인해야 합니다. 회사 소재지 하나를 모든 데이터의 처리 국가로 쓰지 마세요. 다음 값을 실제 문서나 제공자 답변으로 확인하고 근거를 남깁니다.

| `privacy.transfer` 키 | 입력할 내용 |
| --- | --- |
| `recipientLegalName`, `recipientContact` | 계약상 수탁자 법인명과 개인정보 문의 연락처 |
| `countries` | 실제 처리·보관·지원 접근이 발생하는 확인된 국가 목록 |
| `subprocessors` | 관련 재위탁자별 이름·국가·업무. 관련 재위탁자가 없으면 확인한 사실과 근거를 명시 |
| `items` | 필수·선택 문의 내용, 동의 기록, 관련 접속·보안 정보의 실제 범위 |
| `time`, `method` | 접수·보관·알림 전송 등 이전 시점과 암호화 전송 등 실제 방법 |
| `purpose` | 접수 처리·저장·알림 등 확인된 위탁 목적 |
| `retention` | 문의 원본·알림 사본·보안 로그·백업을 포함해 확인한 보유/삭제 기간과 예외 |
| `dpaUrl`, `subprocessorsUrl` | 실제 확인한 문서의 공식 URL |
| `verifiedOn` | 실제 확인한 날짜 |

국외이전은 별도 동의 방식 초안이며, 수집 동의와 분리되어 있습니다. 거부하면 온라인 문의가 제한되고 전화 상담이 대안입니다. Netlify를 처리 수탁자로 이용하는 것과 독립적인 제3자 제공을 혼동하지 않도록 안내했습니다. 네이버메일 수신 경로도 포함해 실제 위탁·이전 범위를 검토하세요. 필수 항목이 확정되기 전에는 온라인 개인정보 접수를 시작하지 마세요.

**화면의 접수 잠금은 서버 접근 제어가 아닙니다.** 정적 HTML의 폼 선언은 감지를 위해 존재합니다. 전화 문의 모드로 공개할 때는 Netlify Forms 감지를 비활성 상태로 유지하세요. 이미 활성화된 사이트라면 Forms 설정과 이전 폼·접수 내역도 확인하세요. 이 저장소만으로 Netlify 계정 설정을 강제할 수 없습니다.

## 5. Netlify 배포와 공식 이메일 알림 등록

사업정보와 개인정보 안내를 먼저 확정하고 아래 순서를 따릅니다. 화면 이름과 제한은 서비스 변경에 따라 다를 수 있으므로 [공식 Forms 설정](https://docs.netlify.com/manage/forms/setup/)과 [알림 문서](https://docs.netlify.com/manage/forms/notifications/)를 배포일에 확인하세요. 가입 요금제·접수량·스팸 처리·초과 요금 조건은 **현재 계정**에서 확인합니다. 영구 무료나 무제한을 약속하지 않습니다.

1. **폼 감지 활성화**: Netlify에서 사이트 프로젝트를 만들고 Forms 설정에서 form detection을 활성화합니다. 이 단계는 미확정 정보를 모두 확정한 뒤에 진행합니다. 테스트는 접근을 제한한 사이트 또는 정식 공개 전 단계에서 하세요. 사이트 접근 제한 기능의 제공 여부·요금은 계정에서 확인해야 합니다.
2. **배포·재배포**: 아래 두 방법 중 하나로 배포합니다. 감지를 켠 뒤 재배포해야 정적 HTML의 `ok-express-inquiry`가 감지됩니다. Forms 목록에서 정확한 이름을 확인하세요.
3. **공식 이메일 알림 등록**: 해당 폼의 **Submission notifications**에서 Email notification을 추가하고 수신 주소를 **`rhwns13@naver.com`**으로 등록합니다. 별도 SMTP나 유료 자동화 서비스는 사용하지 않습니다. 실제 사이트에서 수신 주소와 해당 폼의 연결을 확인하세요.
4. **접수 설정 반영**: 실제 확인 후 `operation.netlifyFormsConfigured`와 `emailNotificationConfigured`를 `true`로 설정합니다. 실제 Netlify HTTPS 주소를 `site.url`에 입력하고, 모든 확인을 마친 뒤 `onlineRequested`를 `true`로 바꿉니다. 다시 빌드·재배포합니다. 빌드 결과가 `ENABLED`여야 하며 `LOCKED`이면 출력된 누락 항목을 확인합니다.
5. **테스트 문의**: 실제 HTTPS 배포 주소에서 비민감 테스트 데이터로 필수/선택 동의, 선택정보 미동의, 정상 제출을 시험합니다. 성공창은 실제 HTTP 성공 응답 뒤에만 표시됩니다. 이 응답만으로 메일 수신까지 입증되지는 않습니다.
6. **Forms 기록과 네이버메일 확인**: Netlify Forms에서 새 기록과 내용을 확인하고, 네이버메일에서 수신·스팸함을 확인합니다. 전화번호, 이사 종류, 출발·도착 지역, 선택정보 동의 여부, 동의문 버전, 국외이전 동의, 참조번호가 본문/기록에 있는지 확인합니다. 테스트 기록은 원본과 메일에서 삭제합니다.

메일 제목용 숨김 `subject` 필드는 **`[OK익스프레스] 새 이사 문의 · OK-<무작위 UUID>`** 형태로 전송됩니다. 참조번호는 브라우저에서 생성하는 문의 식별용 값이며 Netlify가 발급한 서버 접수 ID가 아닙니다. Netlify 공식 알림에서 `subject` 반영 여부를 실제 계정 문서와 테스트로 확인하고, 필요하면 공식 알림 설정의 제목을 개인정보 없이 조정하세요. 본문에서 문의 필드와 동의 기록을 확인합니다. 코드는 알림 설정을 생성하지 않습니다. 알림 지연과 스팸 분류 가능성이 있으므로 즉시 도착을 보장하지 않습니다.

```sh
python3 scripts/package.py
```

생성된 `artifacts/ok-express-netlify.zip`에는 실행 가능한 **정적 HTML/CSS/JavaScript/SVG**가 들어 있습니다. 압축을 풀어 `index.html`이 최상단인 폴더를 Netlify 수동 배포 화면에 올립니다. 계정 UI가 ZIP 업로드를 지원하면 ZIP을 직접 사용해도 됩니다. 소스 ZIP을 배포용으로 올리지 마세요. 정적 폴더의 `_headers`가 보안 헤더를 제공합니다. 설정을 수정했다면 반드시 다시 빌드·업로드하세요. 전화 문의 모드의 배포 파일도 즉시 화면을 표시하지만, 온라인 접수는 별도 조건을 충족해야 합니다.

### B. Git 연동 배포

저장소 파일을 사용자의 GitHub 저장소에 올리고 Netlify에서 연결합니다. GitHub 소스 업로드와 Netlify 사이트 연결·공개 배포는 별도의 작업입니다. ZIP으로 배포하려면 GitHub에서 루트의 `ok-express-netlify.zip` 파일을 연 뒤 **Download raw file** 버튼으로 내려받을 수도 있습니다.

| 설정 | 값 |
| --- | --- |
| Base directory | 저장소 루트 |
| Build command | `python3 scripts/build.py` |
| Publish directory | `dist` |
| Python | 3.12 이상 |

루트의 `netlify.toml`이 같은 설정을 제공합니다. 호스팅 빌드는 개발용 Playwright를 설치하지 않습니다.

실제 도메인을 정하면 `site.url` 설정 후 재빌드합니다. 그때 각 공개 페이지의 canonical·OG URL과 `sitemap.xml`이 생성됩니다. 도메인 미확정 상태에서는 예시 도메인을 출력하지 않습니다. `/thank-you/`는 검색 제외하며, 직접 열어도 접수 성공이라고 표시하지 않습니다. 가짜 주소·후기·별점 기반 구조화 데이터는 없습니다.

## 6. 문의 삭제와 개인정보 운영

**90일은 법정기간이 아니라 제안된 상담 운영안**입니다. 목적을 달성하면 90일까지 기다리지 말고 지체 없이 파기하며, 미계약 문의는 접수일부터 최대 90일까지만 보관합니다. 이 저장소에 자동 삭제 기능은 없습니다. 실제 이행할 담당자를 정하고 주기적인 점검 일정(예: 매일)을 운영하세요. Forms, 이메일, 스팸함, 휴지통, 다운로드한 CSV, 출력물·사본까지 점검합니다.

1. Netlify 대시보드의 해당 사이트 → Forms → `ok-express-inquiry` → 접수 내역에서 종료/기간 경과 항목을 선택해 **삭제**합니다. 단순 스팸 분류·보관 처리와 삭제를 구분하고, 제공되는 휴지통/영구삭제 기능이 있다면 공식 안내에 따라 마무리합니다. 계정 UI와 플랜별 삭제 방법은 현재 문서에서 확인하세요.
2. 네이버메일에서 `[OK익스프레스] 새 이사 문의` 또는 참조번호로 찾아 받은편지함·개인 폴더·스팸함의 사본을 삭제합니다. 휴지통에서도 해당 메시지를 영구삭제합니다. 전달·메일 프로그램 동기화·다운로드한 사본이 있다면 함께 파기합니다.
3. CSV·백업·출력물을 만들었다면 복구/접근 가능한 사본이 남는지 확인합니다. 종이는 분쇄하고, 전자 사본은 서비스 기능과 저장매체 관리 정책에 따라 파기합니다.
4. 제공자 측 백업·로그 최종 삭제 지연은 DPA와 실제 삭제 정책을 확인하고 방침의 국외이전 보유기간에 반영합니다. 확인되지 않은 즉시 완전 삭제를 약속하지 않습니다.
5. 계약으로 전환된 문의는 적용 법적 근거·항목·기간을 확인해 필요한 기록만 별도 보관합니다. 전환되지 않은 문의까지 일괄 5년 보관하지 않습니다.
6. 삭제·동의 철회 등 권리 행사 요청은 제공된 전화/메일로 접수하고, 필요한 본인 확인 후 처리 결과와 제한 사유를 안내합니다. 별도 공개 로그에 고객 정보를 남기지 않습니다.

관리자와 메일 계정은 권한을 최소화하고 다중 인증을 설정하세요. 접수된 자유 입력에 불필요한 개인정보가 있으면 불필요한 부분을 추가 복제하지 말고 필요한 연락 후 파기하세요. 폼의 길이·내용 검사는 사용자 실수를 줄이는 클라이언트 검사이며 서버의 데이터 검증이나 법률 검토를 대신하지 않습니다.

## 7. 보상·계약 운영 점검

`/compensation/`은 사고 접수 → 사실 확인 → 처리 결과 안내의 흐름과 요청받은 보상 취지를 담습니다. 다른 업체의 보험·처리기한을 OK익스프레스의 약속으로 사용하지 않았습니다. 영수증이 없어도 대체 자료를 검토하고, 고객 포장·잔금 지급·당일 미신고만으로 일괄 배제하지 않습니다.

실제 계약에 표준약관을 채택·교부했는지 확인하세요. 일부 분실·훼손의 30일 통지 기준, 은폐 등 예외, 별도의 책임 소멸기간을 현행 원문으로 확인해야 합니다. 30일을 모든 청구의 동일한 소멸시효로 설명하지 마세요. 홈페이지가 표준약관 자동 적용을 뜻하지 않으며, 현행 약관 조문 번호나 예외 내용을 확인하지 않은 채 새로 단정하지 않았습니다. 실제 계약서의 변경 비용·범위 합의와 보상 안내를 일치시키고 확인일을 설정에 기록하세요.

## 8. 검증 재실행

```sh
python3 -m unittest discover -s tests -p 'test_*.py' -v
node --check src/assets/app.js
```

브라우저 검사는 선택 개발 도구입니다. 현재 클라우드에는 Python Playwright 1.62.0과 `/usr/bin/chromium`이 설치되어 있습니다. 다른 컴퓨터에서는 가상환경에 `requirements-dev.txt`를 설치하고 Chromium을 준비합니다.

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m playwright install chromium
# 시스템 Chromium 경로가 다르면 CHROMIUM_PATH에 실행파일 절대경로를 지정합니다.
CHROMIUM_PATH=/usr/bin/chromium .venv/bin/python tests/browser_check.py
```

이 테스트는 임시 폴더에만 합성 사업정보를 만들고 Netlify 응답을 **모의 처리**합니다. 실제 계정으로 테스트 개인정보를 전송하지 않습니다. 공개 `dist/`는 항상 실제 `config.json`에서 빌드합니다. `artifacts/validation.json`은 모의 검증과 실제 미실행 항목을 구분합니다. [검증 보고서](docs/VALIDATION.md)를 함께 보세요.
