# 구현·검증 보고서

기준일: 2026-10-19. 현재 산출물은 **전화 문의 모드**입니다.

## 통과한 검사

- Python 단위/빌드 테스트 **6개 통과**: 기본 접수 잠금, 미확정 필드별 잠금, 도메인 설정 시 canonical·OG·sitemap 생성, HTML 이스케이프, 안전한 출력 폴더와 반복 빌드, 잘못된 도메인 거부.
- `node --check src/assets/app.js` 통과.
- 실제 로컬 HTTP 서버에서 홈·개인정보처리방침·수집 안내·보상 안내가 HTTP 200으로 응답하고, Chromium에서 이미지·스크립트와 접수 잠금이 정상 동작함을 확인했습니다.
- 배포 ZIP의 12개 파일과 소스 ZIP의 무결성·필수 파일을 확인했습니다. 배포 ZIP 최상단에 `index.html`이 있으며, 기본 접수 상태는 잠금입니다.
- 실제 Chromium의 브라우저 검증 **7개 묶음 통과**. 입력·레이아웃·접근성 동작은 브라우저에서 실행했고, Netlify POST 응답은 합성 환경에서 모의 처리했습니다.

| 요청된 확인 항목 | 결과 |
| --- | --- |
| 상단·하단 전화 버튼, 문의 이동 | 전화 링크 일관성·모바일 버튼·첫 화면 문의 이동 확인 |
| 개인정보처리방침·보상 안내 | 페이지 표시 및 360px 가로 넘침 없음 확인 |

| 정상 제출·네트워크 실패·중복 클릭 | **모의 응답으로** 성공/통신 실패/HTTP 503, 입력 유지, 중복 차단 확인 |
| 성공창 표시와 닫기 | 응답 전 미표시, 성공 응답 후 표시, 확인 버튼·Escape로 닫기 및 포커스 복귀 확인 |
| 실제 Netlify Forms 기록 생성 | **미실행**: Netlify 계정 접근 권한 없음 |
| 실제 네이버메일 알림 수신 | **미실행**: 알림 계정 설정·메일함 접근 권한 없음 |

360·390·768·1024·1440px에서 가로 넘침을 확인했습니다. 모바일 메뉴의 키보드 Escape, 동의 기본 미선택, 과거 날짜·입력 길이·상세주소 경고, 미정 날짜, 로컬 미리보기 접수 차단, 직접 감사 페이지를 열었을 때 가짜 성공을 표시하지 않는 동작도 확인했습니다. 네트워크 검사에서는 전송값을 메모리에서만 검사하고 고객 데이터 로그를 만들지 않습니다.

키보드 포커스·오류 요약·dialog 알림과 화면 구성을 점검했지만, 모든 보조공학 기기나 접근성 표준 전체에 대한 인증을 의미하지 않습니다. SVG는 직접 작성한 예시 일러스트이며 실제 현장 사진이 아닙니다.

## 발견 후 수정한 문제

모바일에서 입력창 포커스가 제출 버튼으로 바뀔 때 고정 문의 바가 다시 나타나 클릭을 가로막는 경우가 있었습니다. 폼 전체가 포커스를 가진 동안 고정 바를 숨기도록 수정하고, 네트워크 실패·재시도 검사까지 다시 통과했습니다.

## 미확인 상태와 운영 전 필요한 작업

1. 대표자·사업자등록번호·주소·허가·운영시간·보험 현황·개인정보 담당자 확인.
2. 현재 법령·표준약관·실제 계약서 확인. 관련 사이트가 프록시 403으로 차단되어 현행 원문 확인은 하지 못했습니다.
3. Netlify 현재 DPA·재위탁·이전 국가·보유/삭제 조건 특정 및 별도 동의 안내 확정. 이 정보는 추정하지 않았습니다.
4. Netlify Forms 감지 활성화, 재배포, 공식 Submission notifications 이메일 설정, 실제 접수 기록과 수신 확인.
5. 실제 도메인·방침 시행일·보유기간 삭제 담당자 지정과 실행.

`artifacts/validation.json`에 브라우저 검사 결과가 있습니다. 테스트 데이터가 들어간 활성화 설정은 임시 폴더에서만 만들고 제거하며, 공개 `dist/`에는 포함하지 않습니다. 설치·현재 머신 검증, 설정 초안 저장, 클라우드 환경 게시, Netlify 실제 배포는 서로 별개의 상태입니다. 실제 공개 배포나 메일 연결을 완료했다고 보고하지 않습니다.
